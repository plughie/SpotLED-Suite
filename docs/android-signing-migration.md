# Android signing-key migration

The current contributor APK is signed with the local Android debug identity.
That is suitable for prototype sideloading only. Before public or long-term
distribution, the owner should create a private upload/release key, make at
least two encrypted backups in separate owner-controlled locations, record the
alias and recovery instructions in a password manager, and never commit the
keystore or passwords.

Changing signing identity means Android will not accept a new-key APK as an
in-place update to installations signed with the old key. Existing prototype
users must uninstall the old app and install the first owner-key APK, losing
app-private preferences; provide a settings/export note first if those
preferences matter. After migration, every update must use the same owner key.

No key is generated by this project task: key creation and backup confirmation
are owner-controlled security actions. The project `.gitignore` excludes
`.jks` and `.keystore` files.
